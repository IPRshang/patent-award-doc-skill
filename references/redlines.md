# 红线清单 + 必需输入 + 事实锚点模板

> 本文件经历了 v8 翻转（2026-08-12）：之前"❌ 严禁编造'审查员姓名/授权公告(56)字段引用'"是过度纠正结论；
> 真实事实是——授权公告 (56) 字段页眉载明的审查员姓名 + (56) 字段引用的对比文件，是国家知识产权局实质审查最权威的官方载体，**必须以"原件/截图为准"写入**，不得因本地不存在授权公告 PDF 就自作主张当作"假"删除。
> 把这两条从"红线（严禁）"移到"必写真实"。下述为最新版。

## 一、红线清单（严禁写法，每轮改完必须全文档扫描 0 命中）

- ❌ 编造审查员姓名 / "授权公告(56)字段引用"—— **修订**：仅在**无授权公告原件/截图/官方证明**时禁写；**有原件/截图**则必须按截图原文真实写入。
- ❌ "同日申请实用新型 / 一案两报 / PCT / 海外同族" —— 本件无，仅以否定句出现
- ❌ 把**他人专利**写成"本公司专利池 / 工装系统层"（对比文件只在"新创性"出现，专利池只在"同族/保护成效"出现）
- ❌ 套用**姊妹专利**的财务数据 —— 量化数字必须来自本专利、财务盖章
- ❌ 编造许可 / 出资 / 融资 / 维权诉讼案号
- ❌ 授权公告日写成"授予发明专利权通知书"的发文日（二者不同）
- ❌ 引用错混入本目录的其他案件材料（如发动机仿真、散热仿真案）

扫描：`python scripts/redline_scan.py 申报书.docx`

> 防过度纠正提示：扫描后若发现"王蒙/(56)"再次被算法命中，应先**核对该专利的授权公告截图/PDF 是否在用户手中**。若用户已出示过原件，应保留而非删除。

## 二、必写真实（事实锚点，不可漂移）

| 类别 | 字段 | 来源 |
|---|---|---|
| 申请人 | 名称 / 地址 | 授权公告 (73) 字段 |
| **审查员姓名** | **本专利授权公告 (56) 字段页眉署"审查员 XXX"** | **授权公告原件/截图（不可编造）** |
| **审查员引用的对比文件** | **(56) 字段所列 D1/D2/…** | **授权公告原件/截图（不可编造）** |
| 申请号 / 申请日 | 申请号 (21) / 申请日 (22) | 授权公告 (21)/(22) |
| 授权公告日 | 授权公告 (45) | 授权公告；**≠** 授予发明专利权通知书发文日 |
| 代理机构 / 代理师 | 代理所名称、代码、代理师姓名 | 授权公告 / 委托书 |
| 通知书 | 6 通（或其他具体通数） | 1234 网站"审查信息"截图 |

> 写作模板：`本专利授权公告（CN…B，授权公告日 yyyy-mm-dd）(56) 字段署『审查员 XXX』引用 D1=…、D2=…，是审查员对比文件引用的最权威载体。`

## 三、必需输入文件清单

| 必需度 | 文件 | 用途 |
|---|---|---|
| **必需** | **本专利授权公告原件（PDF 或截图，必含著录项 + (56) 字段）** | **审查员姓名、对比文件引用、授权公告日** |
| 必需 | 本专利授权/申请文本（权利要求书+说明书+附图） | 独权五要素、技术方案、附图 |
| 必需 | 审查流程证据（1234 网站"审查信息"截图 / 登记簿） | 通知书清单、是否 OA/驳回/复审 |
| 必需 | 补正书/修改对照页 | 补正性质、改了什么 |
| 必需 | 代理机构申请前检索报告 | 对比文件来源（D1/D2 + 补充篇）|
| 必需 | 指定对比文件全文 PDF | 三步法比对 |
| 必需 | 本公司相关专利清单 | 同族/保护成效专利池 |

| 推荐 | 维权/许可/运用证据 | 保护成效（无则写"无"）|

## 四、事实锚点模板（写入项目 MEMORY.md，每轮回读防漂移）

```markdown
## 0. 申请人与专利
- 申请人：<公司全称>（<母公司/子公司关系>）
- 内部编号：<ZLxxxx> = <公开号> 严格对应（≠同族、≠相关专利）
- 申请号：<xxxx>；申请日：<yyyy-mm-dd>；授权公告日：<yyyy-mm-dd>；IPC：<xxx>
- 代理机构：<所名>（机构代码 <xxx>），代理师 <姓名>

## 1. 真实通知书清单（铁证）
仅 <N> 通，全程无书面审查意见通知书 / 无驳回 / 无复审：
1. ...（列具体通知书）

## 2. 补正 = 细则第 51 条主动修改（不是 OA 答复）
- 提交时间 / 性质 / 几项形式瑕疵（漏字/衍字/引用不清）
- 未增删技术特征、不含新创性抗辩

## 3. 新创性对比文件（双重来源）
- **D1/D2/...** 来自本专利**授权公告 (56) 字段**（国家知识产权局审查员署名引用，最权威）
  - D1 = <公开号>（公开日 / 申请人 / 名称）
  - D2 = <公开号>（同上）
- **CF...** 来自代理所申请前检索报告（检索人 / 审核人 / 日期 / 系统 / 区域）
  - CF = <公开号>（同上）
- 注：3 篇之间任何"是否他人专利"判断必须在著录层完成，避免把他人专利归入本公司专利池

## 4. 严禁事项（红线）
- 不得写"同日申请 / 一案两报 / PCT / 海外同族"（仅否定句形式）
- 不得把 <他人专利> 写成本公司专利池
- 不得套用姊妹专利财务数据
- 授权公告日 ≠ 通知书发文日
- 防过度纠正：若用户出示授权公告原件/截图，**不得因本地未存档就当作"假"删除审查员姓名/(56)字段引用**——必须以原件为准真实写入

## 5. 本公司相关专利池（用于"保护成效/同族"）
- 基础装置层：<专利号>
- 方法层（本专利）：<专利号>
- 同领域关联：<专利号>
```

## 五、过度纠正的典型案例（本项目 v8 教训）

- 现象：AI 多次把"审查员王蒙 + 授权公告(56)字段引用 D1/D2"当成"无出处的臆造"反复删除，导致申报书事实层反复缩水。
- 根因：AI 自身的核查覆盖范围（仅本地磁盘 + 申报目录）**≠ 用户实际掌握材料范围**（用户手里有授权公告原件）。
- 教训：**未在本地存在 ≠ 不存在**；对待用户提供过的关键截图/原件，应在事实锚点层就以"以原件为准"登记，AI 核查覆盖之外不推断为"假"。
- 改进：见"二、必写真实"与"三、必需输入文件"——把"本专利授权公告原件（PDF 或截图，必含著录项 + (56) 字段）"列为**第一项必需输入**。AI 在每轮开始前应反向询问"请出示授权公告原件/截图"，确认后再下笔。

## 六、此地无银三百两式废话（评审不关心，应删）

> 本项目 v11 教训：评审只看专利的质量 / 运用成效 / 保护成效，不会去质疑"为什么没列某篇第三方专利""谁代理的""图从哪来"。多写这类说明/注脚，反而像在自我辩护、画蛇添足，属于典型的"此地无银三百两"。

应删除（或压根不写）的写法：

- ❌ 同族/保护成效里写"代理机构为广州德科…代理师邓灵、万振雄"——代理机构姓名只在官方要求字段出现，不要塞进叙述性单元格。
- ❌ 图标题后加"（评审 PPT，ZL240801）"之类来源注脚——评审不关心图从哪来，干净图标题即可。
- ❌ 列本公司专利组合时附带撇清："注：CNxxxxx 为某某公司持有的第三方在先专利，系对比文件之一（D2），不属于本公司专利组合，故不列入上述组合"——评审不会去数"为何没列这篇"，这一注反而凸显心虚。直接列本公司专利，不附带解释。
- ❌ 凡"为防评委误解而预先解释/撇清"的句式，一律删。

## 七、结构改写后必须全文复核关键事实

> 本项目 v9→v11 教训：lxml 重写 document.xml（字体修复、补段、repackage）后，python-docx 能正常打开、表数也正常，但**特定文字可能被静默弄丢**（v9 把"审查员王蒙"整段丢了，直到用户下一轮才发现）。

- 任何 lxml 重写 document.xml 后，必须 grep 关键事实确认仍在：审查员姓名 / (56) 字段 / 三步法 / 三篇对比文件公开号 / "保护范围零让步"或等价表述 / 图与嵌套表数量。
- 不能只看"能打开、7 表正常"就放过——能打开≠内容完整。
- 建议：每轮改完跑 `scripts/verify_doc.py 申报书.docx`（结构校验）+ 自定义 grep 关键事实，双保险。
